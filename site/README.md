## 来源与权威边界

**本文件是部署结果的反向导入，不构成历史发布来源证明。** 上述 Git 提交发生在生产部署之后，不能将其提交 SHA 宣称为当次构建或发布 SHA。生产仍以服务器实际字节与文件 SHA-256 作为可核实的文件级事实。

目前 `site/index.html` 含有部署环境的绝对资源路径，包括 `/awkn-home/preview-v14/assets/`。这些依赖资源、Nginx 路由配置、生产部署脚本、正式 QA 门禁和回滚自动化尚未随此提交纳入仓库。

## 推进到 Git → 发布闭环的条件

1. 按文件逐一盘点并登记全部资源引用及其 SHA-256，确定是否属于本站并检查授权与敏感内容。
2. 将需要发布的图片、CSS、JS 等资产纳入明确版本管理；更新 HTML 资源路径，确保从干净克隆可独立构建与预览。
3. 添加可复跑的 HTML 结构、JavaScript、无效链接、桌面和移动端 Chromium 八产品 E2E 验收。
4. 发布构建时写入候选 Git Exact SHA、静态文件哈希、时间和验收回执。通过独立人工审批后部署，部署后检查公网文件、入口与回执一致。
5. PR 保持草稿、不可自动合并或触发生产部署。候选基线经 Owner 审核后再决定是否成为权威源。

任何缺失依赖、失败测试、资源引用失效或生产与候选 SHA 不一致，都应阻止正式发布。
